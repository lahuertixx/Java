Temario 01 · 4 temas

                                    
Programación Java

                                    
Del algoritmo a la máquina virtual, pasando por tipos, expresiones, estructuras de control y objetos: cuatro bloques para escribir y depurar programas Java.

                                


                                

                                    
Tema 1 · Temario 01

                                    
Del problema al primer programa Java

                                    
Programar es describir con precisión los datos, los objetos y las operaciones que resuelven un problema. Un algoritmo es una secuencia ordenada y finita de pasos: antes de codificar conviene representarlo con pseudocódigo o con un diagrama de flujo y verificarlo «a mano». El proceso continúa con la implementación (codificar y probar) y el mantenimiento (corregir errores y adaptar requisitos).

                                    
Java convierte el código fuente en bytecode mediante javac y lo ejecuta con java dentro de la JVM. El JDK incluye compilador, JVM y utilidades; el JRE es la parte necesaria para ejecutar. Ese bytecode estándar explica WORA: «escribe una vez, ejecuta en cualquier parte» siempre que haya una JVM; java -version comprueba la instalación.

                                    
Un programa Java se organiza en clases y necesita un punto de entrada public static void main(String[] args). La sintaxis dice qué se puede escribir y la semántica qué significa; dentro del cuerpo se usan tipos primitivos, String, variables, constantes final, operadores y E/S con System.out o Scanner. Los fallos de sintaxis impiden compilar; los fallos lógicos compilan pero producen un resultado incorrecto.

                                    
    
                                        
  • Fases: análisis y especificación, solución general, verificación, codificación, prueba y mantenimiento.
    • 
                                        
  • Diseño: el pseudocódigo y los diagramas de flujo explican el algoritmo antes de escribir Java.
    • 
                                        
  • Herramientas: JDK (desarrollo), JRE (ejecución) y JVM (intérprete del bytecode); javac genera .class.
    • 
                                        
  • Estructura: importaciones opcionales, declaración de clase, miembros y método main como punto de entrada.
    • 
                                        
  • Datos: ocho tipos primitivos (byte, short, int, long, char, float, double, boolean) más String.
    • 
                                        
  • Declaraciones: variables con tipo e identificador; constantes con final; asignación, concatenación con + y comentarios.
    • 
                                        
  • E/S y errores: System.out.print/println, Scanner con next, nextLine o nextInt; sintaxis frente a lógica.
    • 
                                    

                                    

                                        
Ejemplo · de pseudocódigo a Java

                                        
public class AlgoritmoEdad {
    public static void main(String[] args) {
        // Pseudocódigo: nombre = Ana; anos = 22; nacimiento = 2026 - anos
        String nombre = "Ana";
        int anos = 22;
        int nacimiento = 2026 - anos;
        System.out.print("Nombre: " + nombre);
        System.out.println(" | Nacimiento estimado: " + nacimiento);
    }
}

                                        
Nombre: Ana | Nacimiento estimado: 2004

Tema 2 · Temario 01

                                    
Elementos básicos: tipos, cadenas y entrada/salida

                                    
Java es fuertemente tipado: cada dato tiene un tipo que determina su representación y las operaciones permitidas. Los tipos primitivos son byte, short, int, long, float, double, char y boolean; los identificadores empiezan por letra, subrayado o dólar, distinguyen mayúsculas y minúsculas y no pueden ser palabras reservadas.

                                    
String es un objeto: un literal entre comillas dobles se convierte automáticamente en una instancia inmutable y el operador + permite concatenar cadenas con valores de otros tipos. Una variable reserva un lugar para un valor; una constante declarada con final solo se asigna una vez. Los comentarios, las importaciones y las bibliotecas completan el cuerpo de la clase.

                                    
La salida se escribe con System.out.print y System.out.println; la entrada se lee desde System.in con un Scanner importado de java.util. Un programa interactivo debe mostrar un indicativo antes de leer y, a menudo, hacer eco del dato. Si el compilador detecta un error de sintaxis no hay bytecode; si compila pero hace otra cosa, hay que depurar un error lógico.

                                    
    
                                        
  • Tipos: enteros de 8 a 64 bits, reales float/double, char Unicode y boolean de true o false.
    • 
                                        
  • Identificadores: nombres de clases, métodos y variables; cuenta y Cuenta son distintos.
    • 
                                        
  • Cadenas: literales entre comillas dobles, caracteres entre comillas simples y concatenación con +.
    • 
                                        
  • Declaración: tipo e identificador, con o sin inicialización; final convierte la variable en constante.
    • 
                                        
  • Asignación: = almacena el valor de la expresión de la derecha; los paréntesis de una llamada son obligatorios aunque estén vacíos.
    • 
                                        
  • Bibliotecas: clases agrupadas en paquetes; import java.util.Scanner; debe escribirse antes de la clase.
    • 
                                        
  • E/S: next lee una palabra, nextLine una línea y nextInt un entero; println añade salto de línea.
    • 
                                    

                                    

                                        
Ejemplo · tipos, caracteres y concatenación

                                        
public class TiposYCadenas {
    public static void main(String[] args) {
        int entero = 7;
        double real = 2.5;

        System.out.println(saludo + " " + letra + " " + entero);
        System.out.println("Real: " + real + " | Activo: " + activo);
    }
}

Real: 2.5 | Activo: true

Tema 3 · Temario 01

                                    
Léxico, expresiones y estructuras de control

                                    
El analizador léxico divide el código fuente en tokens: literales, identificadores, operadores y palabras reservadas. Espacios, tabuladores y saltos de línea actúan como separadores. Los enteros pueden escribirse en decimal, hexadecimal con 0X, octal con 0 o binario con 0b, y admiten guiones bajos como 1_000; los reales siguen IEEE 754 con bit de signo, mantisa y exponente.

                                    
Una expresión combina identificadores, literales y operadores y produce un valor con un tipo. La precedencia fija qué operación se hace primero y la asociatividad indica cómo agrupar las de igual nivel; los paréntesis fuerzan el orden. && y || evalúan en cortocircuito de izquierda a derecha, de modo que el primer operando puede proteger al segundo. Java promociona byte, short y char a int, y exige casting explícito para reducir tipos.

                                    
Las sentencias terminan en ; y los bloques con llaves delimitan el ámbito de las variables locales. El flujo de control se decide con if/else, switch (con caída secuencial o con expresiones -> y yield) y los bucles while, do-while y for. Una traza de ejecución permite seguir cada cambio de variables y condición para detectar errores de expresión, condición, selección o repetición.

                                    
    
                                        
  • Léxico: tokens y separadores; literales 0X1A, 012, 0b1010, 1_000, sufijos L/f, boolean, char, String y null.
    • 
                                        
  • IEEE 754: float y double representan signo, mantisa y exponente; amplían el rango con precisión limitada.
    • 
                                        
  • Identificadores: letras, dígitos, subrayado y dólar; no pueden usar palabras reservadas y Java distingue mayúsculas de minúsculas.
    • 
                                        
  • Operadores: aritméticos, relacionales, lógicos y de asignación; cortocircuito, precedencia, asociatividad y evaluación de operandos de izquierda a derecha.
    • 
                                        
  • Conversiones: promoción a int o double, casting con truncamiento, wrappers como Integer y métodos parseInt o parseDouble.
    • 
                                        
  • Biblioteca: Math.sqrt, Math.pow, Math.round y Math.random; import static java.lang.Math.* evita repetir el prefijo.
    • 
                                        
  • Selección: if/else, switch con break y efecto de caída, y switch expression con -> o yield.
    • 
                                        
  • Repetición: inicialización, condición y actualización; while, do-while, for, invariante del bucle, trazas y depuración.
    •

public class SeleccionYRepeticion {

}

Ejemplo · rango aleatorio y traza de do-while

                                        
public class AleatorioYTraza {
    public static void main(String[] args) {
        int tirada = (int) (Math.random() * 6) + 1;
        int contador = 0;
        int acumulado = 0;
        do {
            acumulado += contador;
            contador++;
        } while (contador < 4);
        boolean enRango = tirada >= 1 && tirada <= 6;
        System.out.println("Tirada en [1, 6]: " + enRango);
        System.out.println("Traza acumulado: " + acumulado + ", contador: " + contador);
    }
}

                                        
Tirada en [1, 6]: true
Traza acumulado: 6, contador: 4

                                    

                                    
Qué ocurre: La evaluación de izquierda a derecha, la precedencia y la conversión de tipos explican cada resultado; las estructuras de selección y repetición deciden qué sentencias se ejecutan y cuántas veces.

                                    
Para qué sirve: Sirve para predecir y depurar el flujo de un programa Java: desde la forma de los literales y las expresiones hasta las trazas de bucles y la elección de alternativas.

                                


                                

                                    
Tema 4 · Temario 01

                                    
Fundamentos de la programación orientada a objetos

                                    
La programación orientada a objetos modela entidades con identidad, estado y comportamiento. La abstracción selecciona solo lo relevante para el problema; la encapsulación agrupa datos y operaciones en una clase y oculta los detalles internos. La interfaz pública describe qué ofrece el objeto, no cómo lo implementa, lo que reduce el acoplamiento y facilita cambios sin alterar a quienes lo usan.

                                    
Una clase es una definición común a todas sus instancias; un objeto es una entidad concreta creada en tiempo de ejecución con new. Cada objeto mantiene sus propios valores, aunque comparta métodos con los demás. Una variable de tipo clase no contiene el objeto sino una referencia: puede valer null, los objetos viven en el montículo y el recolector de basura libera los que ya no son accesibles.

                                    
Los atributos guardan el estado y los métodos definen observadores, transformadores y cálculos. Los constructores inicializan la instancia, pueden sobrecargarse y usan this para distinguir atributos de parámetros. Los miembros static y las constantes static final pertenecen a la clase; main es el punto de entrada y una clase conductora permite probar el diseño con resguardos antes de construir la aplicación definitiva.

                                    
    
                                        
  • Modelo: identidad, estado (atributos) y comportamiento (métodos); objetos distintos pueden tener el mismo estado sin ser el mismo objeto.
    • 
                                        
  • Clase e instancia: la clase define la estructura; new reserva memoria, inicializa y devuelve una referencia al objeto creado.
    • 
                                        
  • Encapsulación: ocultación de información, interfaz pública frente a implementación y métodos de acceso para no modificar el estado directamente.
    • 
                                        
  • Referencias: pila para variables locales, montículo para objetos, operador punto para acceder a miembros, null y recolector de basura.
    • 
                                        
  • Métodos: firma, tipo de retorno o void, parámetros formales y argumentos; Java pasa siempre por valor, también copias de referencias.
    • 
                                        
  • Constructores: mismo nombre que la clase y sin tipo de retorno; constructor por defecto, sobrecarga, this y encadenamiento this(...).
    • 
                                        
  • Miembros de clase: static compartido por todas las instancias, constantes static final y método main para iniciar la JVM.
    • 
                                        
  • Convenciones y pruebas: clases UpperCamelCase, variables y métodos lowerCamelCase, constantes UPPER_SNAKE_CASE, paquetes en minúsculas; conductores y resguardos.
    • 
                                    

                                    

                                        
Ejemplo · encapsulación y objetos independientes

                                        
class CuentaBancaria {
    private String titular;
    private double saldo;
    public CuentaBancaria(String titular, double saldo) {
        this.titular = titular;
        this.saldo = saldo;
    }
    public void ingresar(double cantidad) {
        saldo += cantidad;
    }
    public boolean retirar(double cantidad) {
        if (cantidad > saldo) {
            return false;
        }
        saldo -= cantidad;
        return true;
    }
    public double getSaldo() {
        return saldo;
    }
    public String getTitular() {
        return titular;
    }
}
public class PruebaCuenta {
    public static void main(String[] args) {
        CuentaBancaria ana = new CuentaBancaria("Ana", 100.0);
        CuentaBancaria luis = new CuentaBancaria("Luis", 50.0);
        ana.ingresar(25.0);
        boolean ok = luis.retirar(80.0);
        System.out.println(ana.getTitular() + ": " + ana.getSaldo());
        System.out.println(luis.getTitular() + ": " + luis.getSaldo() + " | retirada: " + ok);
    }
}

                                        
Ana: 125.0
Luis: 50.0 | retirada: false

Qué ocurre: La encapsulación protege el estado, new crea objetos independientes y los constructores con this dejan cada instancia lista para usar; static pertenece a la clase, no a cada objeto.

                                    
Para qué sirve: Permite modelar entidades con identidad, estado y comportamiento, probarlas con una clase conductora y entender por qué Java pasa siempre por valor, incluso cuando copia referencias.

Tema 5 · Temario 02

                                    
Sistemas de información: del dato a la información

                                    
Un sistema de información es un conjunto organizado de personas, procedimientos, datos y recursos que recogen, almacenan, procesan y distribuyen información útil para una organización. La parte basada en hardware, software y comunicaciones es el sistema informático.

                                    
Un dato es un hecho aislado sin significado por sí mismo (8, 30); la información es ese dato interpretado en un contexto (nota de alumno: 8, tengo 30 años). La información útil debe ser accesible, actualizada, exacta y precisa, coherente e integrada, y protegida: cada usuario solo lee, modifica o borra lo que tiene autorizado.

                                    
    
                                        
  • Entrada: toma de datos del entorno.
    • 
                                        
  • Almacenamiento: propiedad de recordar esos datos.
    • 
                                        
  • Procesamiento: cálculos según secuencias preestablecidas.
    • 
                                        
  • Salida: generación de información hacia el exterior.
    • 
                                        
  • Tipos: transaccionales (cobros, pagos, entradas y salidas), de soporte a la decisión (comparar alternativas) y estratégicos (ventaja competitiva).
    • 
                                    

                                    

                                        
Ejemplo · de dato a información en TecnoMarket

                                        
Dato:        25
Contexto:    cliente nº 25 = Ana García, con 3 pedidos pendientes
Información: listado de pedidos pendientes del cliente 25 para el administrativo

                                        
Pedido 101 · Portátil Pro · 2 uds. · pendiente
Pedido 104 · Ratón óptico · 5 uds. · pendiente
Pedido 110 · Servidor X   · 1 ud.  · pendiente

                                    

                                    
Qué ocurre: Sin contexto el número 25 no permite decidir nada. Al interpretarlo dentro del proceso de pedidos se convierte en información accionable para el administrativo.

                                    
Para qué sirve: Entender la diferencia entre dato e información explica por qué una base de datos no guarda solo números, sino datos relacionados y con significado para la organización. Hito clave: en 1970 Edgar F. Codd publicó el modelo relacional, base de SQL y de los SGBD modernos.

                                


                                

                                    
Tema 6 · Temario 02

                                    
Almacenamiento físico y sistemas de ficheros

                                    
Un fichero es un conjunto de datos relacionados almacenados como secuencia de información binaria y gestionados como una unidad. El campo es la mínima unidad con sentido; el registro es el conjunto de campos que describe una entidad.

                                    
Los dispositivos pueden ser secuenciales (posiciones contiguas, hay que recorrer los anteriores, como una cinta) o direccionables/de acceso directo (segmentos consultables individualmente, como un disco). Según el acceso: secuencial, directo o aleatorio, y secuencial indexado (un índice localiza registros más rápido).

                                    
    
                                        
  • Redundancia: el mismo dato repetido en varios ficheros.
    • 
                                        
  • Inconsistencia: copias distintas del mismo dato.
    • 
                                        
  • Dependencia programa-datos: cambiar el formato obliga a cambiar los programas.
    • 
                                        
  • Aislamiento, consultas difíciles, falta de integridad y seguridad.
    • 
                                        
  • Dificultad para compartir y controlar la concurrencia.
    • 
                                    

                                    

                                        
Ejemplo · redundancia en dos hojas de cálculo

                                        
clientes.xlsx → Ana García | C/ Mayor 12
pedidos.xlsx  → Pedido 101 | Ana García | C/ Mayor 12
Cambio de domicilio: se actualiza clientes.xlsx pero no pedidos.xlsx

                                        
clientes.xlsx → C/ Mayor 15
pedidos.xlsx  → C/ Mayor 12   ← dirección antigua (inconsistencia)

                                    

                                    
Qué ocurre: Al no existir un mecanismo centralizado, cada aplicación modifica su copia y la empresa pierde confianza en sus datos.

                                    
Para qué sirve: Estos problemas son los que motivan la aparición de las bases de datos: centralizar la información, evitar duplicidades y controlar quién accede a cada dato.

                                


                                

                                    
Tema 7 · Temario 02

                                    
Bases de datos y sistemas de base de datos

                                    
Una base de datos (BD) es un conjunto organizado de datos relacionados, pertenecientes a un mismo contexto, almacenados con la menor redundancia posible y preparados para ser compartidos. Un sistema de base de datos incluye los datos, el SGBD, las aplicaciones, el hardware y las personas que los diseñan, administran y usan.

                                    
    
                                        
  • Ventajas: menor redundancia, coherencia, datos compartidos, consultas flexibles, integridad, seguridad, control de concurrencia, copias y recuperación.
    • 
                                        
  • Inconvenientes: coste, complejidad y necesidad de personal cualificado.
    • 
                                        
  • DBA: seguridad, permisos, copias y rendimiento. Desarrollador: crea la aplicación. Usuario final: introduce y consulta pedidos.
    • 
                                    

                                    

                                        
Ejemplo · sustituir tres hojas por tablas

                                        
CREATE TABLE Clientes (IdCliente INT PRIMARY KEY, Nombre VARCHAR(50));
CREATE TABLE Productos (IdProducto INT PRIMARY KEY, Precio DECIMAL(8,2));
CREATE TABLE Pedidos (IdPedido INT PRIMARY KEY, IdCliente INT);
CREATE TABLE DetallePedido (IdDetalle INT PRIMARY KEY, IdPedido INT,
                            IdProducto INT, Cantidad INT);

                                        
IdCliente, IdProducto, IdPedido, IdDetalle e IdEmpleado como claves primarias.
DetallePedido resuelve la relación N:M entre pedidos y productos.

                                    

                                    
Qué ocurre: El dato se almacena una sola vez y cualquier cambio se refleja automáticamente en todas las consultas, en lugar de repetirse en tres archivos distintos.

                                    
Para qué sirve: Es el concepto central del temario: la BD no es solo un archivo grande, sino un conjunto estructurado y gestionado de datos compartidos.

                                


                                

                                    
Tema 8 · Temario 02

                                    
Niveles de abstracción e independencia de datos

                                    
El nivel interno o físico describe cómo se guardan realmente los datos (archivos, bloques, discos, índices). El nivel conceptual es la estructura lógica global y sus relaciones (modelo E/R). El nivel externo es la visión parcial de cada usuario o aplicación.

                                    
El esquema es la estructura estable; la instancia son los datos en un momento dado. La independencia física permite cambiar índices o ubicación sin afectar al esquema conceptual; la independencia lógica permite añadir un atributo sin reescribir las vistas de usuario si se mantienen las vistas externas.

                                    

                                        
Ejemplo · una vista para el usuario

                                        
CREATE VIEW ListadoClientes AS
  SELECT Nombre, Teléfono FROM Clientes;

SELECT * FROM ListadoClientes;

                                        
Nombre       | Teléfono
Ana García   | 600123456
Luis Martín  | 600987654

                                    

                                    
Qué ocurre: El usuario ve solo Nombre y Teléfono aunque la tabla tenga ocho columnas. Si se cambia el almacenamiento a otro disco, la vista sigue funcionando sin modificaciones.

                                    
Para qué sirve: La abstracción separa «cómo se guarda» de «qué se ve», lo que permite cambiar la parte física o añadir columnas sin romper las aplicaciones de los usuarios.

                                


                                

                                    
Tema 9 · Temario 02

                                    
Modelos de datos y clasificación de los SGBD

                                    
Los modelos de datos son formas de representar la realidad: jerárquico (árbol), de red (grafo más flexible), relacional (tablas relacionadas por claves), orientado a objetos (objetos y sus características) y NoSQL (documentos, columnas, grafos o clave-valor). NoSQL permite grabaciones muy veloces y miles de peticiones simultáneas cuando pesan más la disponibilidad y la rapidez que la validación compleja de relaciones.

                                    
    
                                        
  • Por modelo: relacional, red, jerárquico, orientado a objetos, NoSQL.
    • 
                                        
  • Por usuarios: monousuario o multiusuario.
    • 
                                        
  • Por ubicación: centralizado (una máquina, aunque atienda a muchos usuarios) o distribuido (datos y software repartidos en varios sitios en red).
    • 
                                        
  • Por licencia: libres (MySQL, PostgreSQL, MariaDB) o propietarios (Oracle, SQL Server).
    • 
                                    

                                    

                                        
Ejemplo · elegir SGBD para TecnoMarket

                                        
Requisitos: 500 clientes, 200 productos, 4 administrativos, coste cero.
Elección: modelo relacional + servidor centralizado + MySQL (community).
Alternativa válida: PostgreSQL (libre, escalable, control de accesos).

                                        
Un único servidor atiende a los 4 administrativos de forma simultánea.

                                    

                                    
Qué ocurre: «Centralizado» describe dónde están los datos; «multiusuario» describe cuántos usuarios atienden. Un SGBD centralizado puede ser multiusuario sin ser distribuido.

                                    
Para qué sirve: Saber clasificar los SGBD ayuda a elegir la herramienta adecuada según coste, escala, licencia y necesidades de relación entre datos.

                                


                                

                                    
Tema 10 · Temario 02

                                    
Funciones, componentes y objetivos del SGBD

                                    
El SGBD (DBMS) es un software y un conjunto coordinado de programas, procedimientos y lenguajes que permiten definir, crear, mantener y acceder de forma controlada a una base de datos.

                                    
    
                                        
  • Definición/descripción (DDL): crea y modifica estructuras.
    • 
                                        
  • Manipulación (DML): inserta, actualiza y borra datos.
    • 
                                        
  • Utilización/control (DCL): permisos, recuperación y transacciones.
    • 
                                        
  • Componentes: lenguajes, estructuras de datos (ficheros, diccionario de datos, índices), gestor de ficheros, gestor de datos, procesador de consultas, compilador DDL y precompilador DML.
    • 
                                        
  • Metadatos: tablas, columnas, tipos, restricciones, usuarios, permisos, índices y procedimientos, guardados en el diccionario/catálogo del sistema.
    • 
                                        
  • Objetivos: integridad, atomicidad, concurrencia con bloqueos, seguridad, recuperación, disponibilidad, administración, comunicación y escalabilidad.
    • 
                                    

                                    

                                        
Ejemplo · qué ocurre al consultar

                                        
SELECT * FROM Clientes;

                                        
500 filas de cliente sin que el usuario sepa en qué sector del disco están.

                                    

                                    
Qué ocurre: El procesador de consultas traduce la sentencia, el gestor de ficheros localiza el bloque y el gestor de datos devuelve las filas. Si falla el hardware durante una escritura, el SGBD usa copias y registros para dejar la BD coherente.

                                    
Para qué sirve: Conocer los componentes explica por qué una simple consulta esconde mucho trabajo: traducción, localización, permisos y recuperación.

                                


                                

                                    
Tema 11 · Temario 02

                                    
Lenguajes de una base de datos: DDL, DML, DQL y DCL

                                    
El lenguaje de una BD se divide en varios sublenguajes según qué haga. DDL (Data Definition Language) define estructuras, tipos y restricciones con CREATE, ALTER y DROP; incluye DSDL para características físicas. DML (Data Manipulation Language) mueve datos con INSERT, UPDATE y DELETE. DQL es la parte de consulta, identificada con SELECT. DCL (Data Control Language) gestiona permisos con GRANT y REVOKE. Los 4GL son herramientas de desarrollo rápido, como asistentes de Access u Oracle Developer Suite.

                                    

                                        
Ejemplo · los cuatro sublenguajes en acción

                                        
-- DDL: estructura
CREATE TABLE Clientes (IdCliente INT PRIMARY KEY, Nombre VARCHAR(50));
-- DML: datos
INSERT INTO Clientes VALUES (1, 'Ana García');
-- DQL: consulta
SELECT Nombre FROM Clientes WHERE IdCliente = 1;
-- DCL: permiso
GRANT SELECT ON Clientes TO usuario1;

                                        
Tabla creada · 1 fila insertada · «Ana García» devuelta · permiso concedido.

                                    

                                    
Qué ocurre: Clasificar bien la operación evita confundir «crear la tabla» (estructura) con «introducir pedidos» (datos). Cada sublenguaje tiene un propósito distinto dentro del mismo SQL.

                                    
Para qué sirve: Es la base para escribir sentencias SQL correctamente y saber a quién corresponde cada responsabilidad en la administración de la BD.

                                


                                

                                    
Tema 12 · Temario 02

                                    
Modelo entidad-relación: entidades, atributos y claves

                                    
Una entidad es un objeto real o conceptual del dominio (CLIENTE, OBRA, MÁQUINA). Es fuerte si existe por sí misma y débil si necesita otra para identificarse. Los atributos pueden ser simples, compuestos (direccion_fiscal[tipo_via, numero, codigo_postal, provincia]), multivaluados (telefonos_contacto, certificaciones_fabricante) o derivados (antiguedad_maquina, importe_total_averias, calculables a partir de fechas y costes; se dibujan con óvalos discontinuos).

                                    
    
                                        
  • Clave primaria: identifica de forma única cada instancia.
    • 
                                        
  • Clave candidata: podría ser PK; alterna: candidata no elegida.
    • 
                                        
  • Clave foránea: referencia a otra entidad.
    • 
                                        
  • Discriminador parcial: num_incidencia, num_revision en entidades débiles.
    • 
                                    

                                    

                                        
Ejemplo · diccionario de datos de SerraMAQ

                                        
CLIENTE       → entidad fuerte,  cod_cliente (PK), NIF/CIF, razón social
MÁQUINA       → entidad fuerte,  cod_maquina (PK), número_bastidor (único)
PARTE_AVERÍA  → entidad débil,   (cod_maquina, num_incidencia) (PK compuesta)
REPUESTO      → entidad débil,   ref_repuesto (PK), proveedor (FK)
EMPLEADO      → entidad fuerte,  cod_empleado (PK)

                                        
Catálogo con 10 entidades documentadas: CLIENTE, OBRA, MÁQUINA, EMPLEADO, MECÁNICO, OPERADOR, PARTE_AVERÍA, REVISIÓN_PREVENTIVA, REPUESTO y PROVEEDOR.

                                    

                                    
Qué ocurre: Al separar los tipos de atributos antes de dibujar el diagrama se evita guardar una lista de teléfonos dentro de una sola columna y se sabe qué atributos se calcularán en lugar de almacenarse.

                                    
Para qué sirve: Una buena documentación de entidades, atributos y claves es el paso previo imprescindible para dibujar el modelo E/R y después crear las tablas.

                                


                                

                                    
Tema 13 · Temario 02

                                    
Relaciones y cardinalidad en el modelo E/R

                                    
Una relación es una asociación entre entidades. Puede ser normal o identificativa, binaria o recursiva, y tiene cardinalidad 1:1, 1:N o N:M. La participación se escribe como (mín,máx) e indica si la intervención es obligatoria (1) u opcional (0).

                                    

                                        
Ejemplo · relaciones del caso SerraMAQ

                                        
[CLIENTE]──(1,N) PROMUEVE ──(1,1)[OBRA]
[OBRA]──(0,N) ASIGNA/ALQUILA ──(0,N)[MÁQUINA]
  atributos: fecha_inicio, fecha_prevista_fin, precio_alquiler_diario, horas_uso_estimadas
[EMPLEADO supervisor]──(0,N) SUPERVISA ──(0,1)[EMPLEADO subordinado]  (recursiva 1:N)
[MÁQUINA]──(0,N) IDENTIFICA(Avería) ──(1,1)[PARTE_AVERÍA]
[MECÁNICO]──(0,N) INTERVIENE ──(0,N)[PARTE_AVERÍA]
[PARTE_AVERÍA]──(1,N) CONSUME ──(0,N)[REPUESTO]
[PROVEEDOR]──(0,N) SUMINISTRA ──(1,1)[REPUESTO]

                                        
En TecnoMarket: pedidos(1) ── DetallePedido ── Productos(3): una relación N:M se descompone en dos 1:N.

                                    

                                    
Qué ocurre: La cardinalidad (0,N) permite una obra sin máquinas asignadas todavía; la (1,1) exige que cada parte de avería pertenezca a una máquina.

                                    
Para qué sirve: La cardinalidad y la participación son las decisiones que más influyen después en las claves foráneas y en las restricciones de las tablas.

                                


                                

                                    
Tema 14 · Temario 02

                                    
Entidades débiles, jerarquías ISA y decisiones de diseño

                                    
Una entidad débil no tiene clave propia completa: su identificador se forma con la clave de la entidad fuerte más un discriminador parcial. En SerraMAQ: (cod_maquina, num_incidencia) y (cod_maquina, num_revision).

                                    
Una jerarquía ISA especializa una entidad en subtipos. En SerraMAQ, EMPLEADO se especializa en MECÁNICO y OPERADOR: es parcial (puede haber empleados sin subtipo) y exclusiva (nadie es las dos cosas a la vez). Atributos propios: nivel_tecnico y certificaciones_fabricante para mecánicos; numero_licencia_especial y tipos_maquinaria_autorizada para operadores.

                                    

                                        
Ejemplo · tablas de subtipos

                                        
CREATE TABLE Empleado (cod_empleado INT PRIMARY KEY, nombre VARCHAR(50), tipo VARCHAR(20));
CREATE TABLE Mecanico (cod_empleado INT PRIMARY KEY REFERENCES Empleado, nivel_tecnico VARCHAR(20));
CREATE TABLE Operador (cod_empleado INT PRIMARY KEY REFERENCES Empleado, numero_licencia VARCHAR(20));
INSERT INTO Empleado VALUES (7, 'Juan', 'Mecánico');
INSERT INTO Mecanico VALUES (7, 'Nivel 3');

                                        
EMPLEADO(7, 'Juan', 'Mecánico') + MECANICO(7, 'Nivel 3'), sin fila en OPERADOR.

                                    

                                    
Qué ocurre: Si se intentase insertar a Juan también en OPERADOR, la restricción de exclusividad lo rechazaría. Si se borra la máquina, sus partes de avería se borran en cascada por ser entidades débiles.

                                    
Para qué sirve: Documentar estas decisiones antes de crear el esquema evita cardinalidades mal interpretadas y tener que rehacer la base de datos una vez implantada.

                                


                                

                                    
Tema 15 · Temario 02

                                    
Paso del modelo E/R al modelo relacional

                                    
El paso al modelo relacional sigue reglas fijas: cada entidad fuerte se convierte en una tabla con su PK; cada atributo multivaluado, en una tabla aparte con la PK del padre; cada atributo compuesto, en columnas separadas; cada derivado se calcula (vista o columna calculada), no se almacena; cada relación N:M se resuelve con una tabla de intersección de PK compuesta; cada 1:N con una FK en el lado N; cada 1:1 con una FK UNIQUE; la jerarquía ISA con una tabla única y discriminador o tablas de subtipo; la entidad débil con PK compuesta que incluye la FK identificativa.

                                    

                                        
Ejemplo · esquema relacional de SerraMAQ

                                        
CREATE TABLE Cliente (cod_cliente INT PRIMARY KEY, nif VARCHAR(20),
                      razon_social VARCHAR(80), tipo_via VARCHAR(20),
                      numero VARCHAR(10), codigo_postal VARCHAR(5), provincia VARCHAR(40));
CREATE TABLE TelefonoCliente (cod_cliente INT REFERENCES Cliente, etiqueta VARCHAR(20),
                              numero VARCHAR(15), PRIMARY KEY (cod_cliente, etiqueta));
CREATE TABLE Obra (cod_obra INT PRIMARY KEY, nombre_proyecto VARCHAR(80),
                   ubicacion VARCHAR(80), cod_cliente INT REFERENCES Cliente);
CREATE TABLE AsignaAlquila (cod_obra INT REFERENCES Obra, cod_maquina INT,
                            fecha_inicio DATE, precio_alquiler_diario DECIMAL(8,2),
                            PRIMARY KEY (cod_obra, cod_maquina));
CREATE TABLE ParteAveria (cod_maquina INT, num_incidencia INT, fecha_reporte DATE,
                          gravedad VARCHAR(20), PRIMARY KEY (cod_maquina, num_incidencia));

                                        
10 entidades convertidas en tablas más tablas de apoyo para teléfonos, certificaciones y tipos de maquinaria autorizada.

                                    

                                    
Qué ocurre: La relación identificativa se traduce en una FK que forma parte de la PK, garantizando que no exista una avería sin máquina.

                                    
Para qué sirve: Es el puente entre el diseño conceptual y el esquema físico: cualquier error de cardinalidad detectado aquí se corrige antes de crear las tablas.

                                


                                

                                    
Tema 16 · Temario 02

                                    
Álgebra relacional

                                    
El álgebra relacional es un lenguaje formal de consultas sobre relaciones (tablas). Sus operadores unarios son selección σ, proyección π y renombrado ρ; los binarios son unión ∪, diferencia −, intersección ∩, producto cartesiano ×, junta ⋈, división ÷ y agregación G. σ filtra filas, π selecciona columnas y elimina duplicados, ⋈ combina filas por una condición y ÷ responde a preguntas de «para todos».

                                    

                                        
Ejemplo · tres consultas en álgebra

                                        
1) π NombreProducto (σ Precio > 500 (Productos))
2) π Nombre (Clientes ⋈ Pedidos)   con Clientes.IdCliente = Pedidos.IdCliente
3) π IdProducto (Pedidos ⋈ DetallePedido) ÷ π IdCliente (Clientes)

                                        
1) Portátil Pro, Servidor X
2) Ana García, Luis Martín (clientes con al menos un pedido, sin repetir)
3) Productos comprados por TODOS los clientes.

                                    

                                    
Qué ocurre: El álgebra es la base teórica que el optimizador del SGBD usa para traducir y reordenar consultas SQL. La división responde a «para todos», algo que en SQL se escribe con NOT EXISTS o HAVING COUNT.

                                    
Para qué sirve: Entender estos operadores ayuda a leer una consulta SQL como una composición de filtros, columnas y juntas, y a saber qué resultado se espera antes de ejecutarla.

                                


                                

                                    
Tema 17 · Temario 02

                                    
SQL: definición e integridad (DDL)

                                    
SQL es el lenguaje estándar para definir, consultar y manipular bases de datos relacionales, asociado al modelo de Codd. Las restricciones de integridad se clasifican en integridad de entidad (PK no nula y única), referencial (FK apunta a una PK existente) y de dominio o semántica (tipos, CHECK, DEFAULT).

                                    
    
                                        
  • NOT NULL: el campo no puede quedar vacío.
    • 
                                        
  • UNIQUE: no admite valores repetidos.
    • 
                                        
  • PRIMARY KEY: identificador único de la fila.
    • 
                                        
  • FOREIGN KEY: referencia a otra tabla.
    • 
                                        
  • CHECK: condición que debe cumplir el valor.
    • 
                                        
  • DEFAULT: valor por defecto si no se indica otro.
    • 
                                    

                                    

                                        
Ejemplo · esquema de TecnoMarket

                                        
CREATE TABLE Clientes (IdCliente INT PRIMARY KEY, Nombre VARCHAR(50) NOT NULL,
                       Dirección VARCHAR(100), Teléfono VARCHAR(15), Email VARCHAR(100) UNIQUE);
CREATE TABLE Productos (IdProducto INT PRIMARY KEY, NombreProducto VARCHAR(50),
                        Precio DECIMAL(8,2) CHECK (Precio > 0), Stock INT DEFAULT 0);
CREATE TABLE Pedidos (IdPedido INT PRIMARY KEY, FechaPedido DATE,
                      IdCliente INT REFERENCES Clientes(IdCliente));
CREATE TABLE DetallePedido (IdDetalle INT PRIMARY KEY, IdPedido INT REFERENCES Pedidos,
                            IdProducto INT REFERENCES Productos, Cantidad INT CHECK (Cantidad > 0),
                            UNIQUE(IdPedido, IdProducto));

                                        
Cuatro tablas creadas y registradas en el diccionario de datos. La combinación IdPedido+IdProducto evita duplicar un producto en el mismo pedido.

                                    

                                    
Qué ocurre: Al insertar un pedido con IdCliente = 999 inexistente, el SGBD rechaza la fila y no queda un pedido huérfano.

                                    
Para qué sirve: Definir bien las restricciones en el DDL evita tener que validar esos casos después en el código de la aplicación.

                                


                                

                                    
Tema 18 · Temario 02

                                    
SQL: manipulación y consulta básica (DML/DQL)

                                    
La manipulación de datos usa INSERT para añadir filas, UPDATE para modificarlas y DELETE para borrarlas. La consulta usa SELECT con WHERE para filtrar, LIKE para patrones de texto, ORDER BY para ordenar y LIMIT para recortar el número de filas. Una consulta SELECT no modifica la BD: devuelve conjuntos de filas.

                                    

                                        
Ejemplo · alta, cambio, borrado y consulta

                                        
INSERT INTO Clientes VALUES (1, 'Ana García', 'C/ Mayor 12', '600123456', 'ana@tecno.es');
UPDATE Productos SET Stock = Stock - 2 WHERE IdProducto = 1;
DELETE FROM Productos WHERE IdProducto = 5;
SELECT Nombre, Email FROM Clientes
WHERE Nombre LIKE 'A%' ORDER BY Nombre LIMIT 10;

                                        
1 fila insertada · Stock de 20 a 18 · 1 fila eliminada (o error si hay detalle que la referencia, salvo ON DELETE CASCADE) · nombres que empiezan por A ordenados.

                                    

                                    
Qué ocurre: WHERE filtra antes de ordenar. Sin WHERE se devuelven los 500 clientes; con LIMIT 10 solo los diez primeros del orden indicado.

                                    
Para qué sirve: Son las operaciones diarias de cualquier usuario de una BD: dar de alta clientes, actualizar stock y buscar información concreta.

                                


                                

                                    
Tema 19 · Temario 02

                                    
JOIN, GROUP BY, subconsultas y vistas

                                    
Un JOIN combina filas de varias tablas: INNER JOIN solo coincidencias, LEFT JOIN conserva todas las filas de la izquierda, RIGHT y FULL amplían la cobertura. Sin condición se genera un producto cartesiano con combinaciones espurias. GROUP BY agrupa filas y HAVING filtra grupos ya formados, mientras que WHERE filtra filas antes de agrupar. Una subconsulta puede devolver un conjunto (IN), comprobar existencia (EXISTS) o un único valor (escalar). Una vista guarda la definición de una consulta y se comporta como una tabla derivada, sin duplicar datos.

                                    

                                        
Ejemplo · ventas por cliente

                                        
SELECT c.Nombre, p.FechaPedido, pr.NombreProducto, dp.Cantidad
FROM Clientes c
JOIN Pedidos p ON c.IdCliente = p.IdCliente
JOIN DetallePedido dp ON p.IdPedido = dp.IdPedido
JOIN Productos pr ON dp.IdProducto = pr.IdProducto;

SELECT c.Nombre, SUM(dp.Cantidad * pr.Precio) AS Total
FROM Clientes c JOIN Pedidos p ON c.IdCliente = p.IdCliente
JOIN DetallePedido dp ON p.IdPedido = dp.IdPedido
JOIN Productos pr ON dp.IdProducto = pr.IdProducto
GROUP BY c.IdCliente, c.Nombre
HAVING SUM(dp.Cantidad * pr.Precio) > 1000
ORDER BY Total DESC;

CREATE VIEW VentasCliente AS
  SELECT c.Nombre, SUM(dp.Cantidad * pr.Precio) AS Total
  FROM Clientes c JOIN Pedidos p ON c.IdCliente = p.IdCliente
  JOIN DetallePedido dp ON p.IdPedido = dp.IdPedido
  JOIN Productos pr ON dp.IdProducto = pr.IdProducto
  GROUP BY c.IdCliente, c.Nombre;
SELECT * FROM VentasCliente WHERE Total > 1000;

                                        
Ana García | 2026-11-02 | Portátil Pro | 2
Clientes con compras superiores a 1000 €, ordenados de mayor a menor total.

                                    

                                    
Qué ocurre: HAVING filtra grupos después del GROUP BY; WHERE filtra filas antes. La vista siempre muestra datos actualizados porque no guarda copias, solo la consulta.

                                    
Para qué sirve: Casi todas las consultas reales de una empresa necesitan juntar varias tablas, agrupar importes y filtrar resultados; las vistas además simplifican consultas repetidas y controlan qué ve cada usuario.

                                


                                

                                    
Tema 20 · Temario 02

                                    
Transacciones, concurrencia, seguridad y recuperación

                                    
Una transacción es un conjunto de acciones que cambia el contenido de la BD y debe cumplir las propiedades ACID: atomicidad (se aplica completa o no se aplica), coherencia (deja la BD en un estado válido), aislamiento (no interfere con otras transacciones) y durabilidad (una vez confirmada, sobrevive a un fallo).

                                    
    
                                        
  • Concurrencia: bloqueos para que dos administrativos que editan el mismo pedido no se corrompan mutuamente.
    • 
                                        
  • Seguridad: el DBA crea usuarios y concede o retira permisos.
    • 
                                        
  • Recuperación: copias de seguridad automatizables y registros de transacciones ante fallos de hardware, software o cancelaciones.
    • 
                                    

                                    

                                        
Ejemplo · descontar stock de forma segura

                                        
START TRANSACTION;
UPDATE Productos SET Stock = Stock - 2 WHERE IdProducto = 1;
INSERT INTO DetallePedido VALUES (10, 1, 1, 2);
COMMIT;   -- o ROLLBACK si el INSERT falla
GRANT SELECT ON Clientes TO usuario1;
REVOKE INSERT ON Pedidos FROM usuario2;

                                        
Con COMMIT: stock 18 y detalle insertado. Con ROLLBACK: stock vuelve a 20 y no queda detalle.

                                    

                                    
Qué ocurre: Si falla algo a mitad del proceso, el SGBD deshace la operación parcial y la BD nunca queda «a medias». Los bloqueos evitan que dos usuarios modifiquen el mismo registro a la vez.

                                    
Para qué sirve: ACID es lo que permite confiar en una base de datos cuando varios usuarios trabajan al mismo tiempo o cuando se produce un fallo inesperado.

                                


                                

                                    
Tema 21 · Temario 02

                                    
Normalización: 1FN, 2FN, 3FN y BCNF

                                    
La normalización organiza las tablas para eliminar redundancia y anomalías de inserción, actualización y borrado, basándose en las dependencias funcionales. 1FN exige valores atómicos y sin grupos repetitivos (los teléfonos multivaluados van a su propia tabla). 2FN exige estar en 1FN y que todo atributo no clave dependa de toda la clave primaria, no de una parte. 3FN exige estar en 2FN y sin dependencias transitivas de la clave. BCNF exige que todo determinante sea una clave candidata.

                                    

                                        
Ejemplo · tabla con problemas y su descomposición

                                        
-- Tabla problemática: repite NombreCliente y NombreProducto en cada línea
-- Pedidos(IdPedido, Fecha, IdCliente, NombreCliente, IdProducto, NombreProducto, Cantidad)

CREATE TABLE Pedidos (IdPedido INT PRIMARY KEY, Fecha DATE, IdCliente INT);
CREATE TABLE DetallePedido (IdPedido INT, IdProducto INT, Cantidad INT,
                            PRIMARY KEY (IdPedido, IdProducto));
CREATE TABLE Productos (IdProducto INT PRIMARY KEY, NombreProducto VARCHAR(50), Precio DECIMAL(8,2));

                                        
Tres tablas en 3FN: el nombre del cliente va en Clientes y el del producto en Productos.

                                    

                                    
Qué ocurre: Cambiar el nombre de un cliente requiere una sola UPDATE en Clientes en lugar de decenas de filas de detalle. En 2FN, un atributo que depende solo de IdProducto no debe estar en una tabla cuya clave sea (IdPedido, IdProducto).

                                    
Para qué sirve: Normalizar evita inconsistencias y ahorra espacio; es el criterio para decidir cuándo una tabla debe dividirse en dos.

Tema 23 · Temario 03

                                    
Componentes del ordenador y arquitectura de von Neumann

                                    
Un ordenador es un sistema que recibe datos, los procesa y devuelve resultados. La arquitectura clásica de von Neumann organiza la CPU, la memoria, los dispositivos de entrada/salida y el bus de direcciones, datos y control; instrucciones y datos conviven en la misma memoria y la CPU repite el ciclo obtener → decodificar → ejecutar.

                                    
La CPU contiene la unidad de control, los registros y la ALU (operaciones aritméticas y lógicas); sus núcleos y su frecuencia en GHz marcan cuántos ciclos puede realizar por segundo. Cerca de ella está la caché L1/L2/L3, mucho más rápida que la RAM (volátil), mientras que la ROM guarda el firmware de arranque (BIOS/UEFI). El almacenamiento masivo se reparte entre SSD (memoria flash, sin piezas móviles) y HDD (platos magnéticos), y todo se conecta mediante la placa base, su chipset, ranuras y puertos, alimentado por la fuente y completado con periféricos de entrada, salida y almacenamiento.

                                    
Las unidades encadenan 1 byte = 8 bits y 1 GB ≈ 1024 MB; el rendimiento real no depende solo del procesador, sino del conjunto CPU + RAM + disco + bus + controladores. Por eso los requisitos del temario distinguen mínimos de recomendados: Windows 11 pide CPU de 64 bits a ≥1 GHz y 2 núcleos, 4 GB de RAM, 64 GB de disco, UEFI con Secure Boot y TPM 2.0, pero 8 GB y SSD hacen la experiencia fluida; Ubuntu Desktop 24.04 LTS parte de 2 núcleos a 2 GHz, 4 GB y 25 GB.

                                    
    
                                        
  • von Neumann: memoria única para instrucciones y datos, CPU con ALU y unidad de control, E/S y bus que conecta todo.
    • 
                                        
  • Ciclo de instrucción: el contador de programa (PC) apunta a la siguiente instrucción; se trae al registro de instrucciones, se decodifica y se ejecuta.
    • 
                                        
  • Memoria: registros → caché L1/L2/L3 → RAM → SSD/HDD; cuanto más lejos de la CPU, más capacidad y más latencia.
    • 
                                        
  • ROM/firmware: conserva el código de arranque incluso sin corriente; UEFI/TPM participan en el arranque seguro.
    • 
                                        
  • Almacenamiento: un SSD de 500 GB puede dividirse en 150 GB para el sistema y 350 GB para datos (particiones lógicas, no físicas).
    • 
                                        
  • Periféricos: teclado, ratón, escáner y micrófono entran; monitor, impresora y altavoces salen; discos y memorias USB son E/S y almacenamiento.
    • 
                                        
  • Rendimiento: 1 Gb/s equivale a unos 125 MB/s; una RAM insuficiente o un HDD lento pueden frenar una CPU potente.
    • 
                                    

                                    

                                        
Ejemplo · ciclo de instrucción en von Neumann

                                        
RAM:
  0x1000 = LOAD A, [0x2000]
  0x1004 = ADD A, 3
  0x1008 = STORE [0x3000], A
Dato en 0x2000 = 7
Registros iniciales: PC=0x1000, A=0

                                        
1. PC=0x1000 → bus de direcciones 0x1000 → bus de datos trae LOAD A,[0x2000]
2. Decodifica → bus lee 0x2000=7 → A=7 → PC=0x1004
3. Decodifica ADD → ALU calcula 7+3=10 → A=10 → PC=0x1008
4. Decodifica STORE → bus escribe 10 en 0x3000
Resultado: memoria[0x3000] = 10 ; PC=0x100C (fin del programa)

Equipo: CPU 2 núcleos a 2,0 GHz · RAM 4 GB · SSD 120 GB · UEFI + TPM 2.0
Red del aula: 1 Gb/s · Impresora USB (controlador instalado)
Referencia Windows 11: 2 núcleos ≥1 GHz · 4 GB RAM · 64 GB · UEFI/Secure Boot/TPM 2.0
Referencia Ubuntu 24.04: 2 núcleos ≥2 GHz · 4 GB RAM · 25 GB

RAM          4 GB      4 GB         sí (justo; 8 GB recomendado)

Qué ocurre: La CPU y la memoria se comunican por el bus y la ALU ejecuta las operaciones, pero el conjunto rinde al ritmo del componente más lento: por eso importan la caché, la RAM, el tipo de disco y los controladores, no solo los GHz.

                                    
Para qué sirve: Conocer el hardware y sus unidades permite elegir e instalar un sistema operativo compatible, interpretar requisitos y diagnosticar por qué un equipo va lento.

                                


                                

                                    
Tema 24 · Temario 03

                                    
Software de sistema, sistema operativo y licencias

                                    
El software de sistema hace funcionar el equipo: el sistema operativo (SO), los controladores (drivers), las utilidades de mantenimiento y el firmware. El software de aplicación resuelve tareas del usuario: el navegador, el procesador de textos o el editor de imágenes. El SO actúa como intermediario y aporta dos ideas clave: abstracción (la aplicación guarda un archivo sin conocer sectores físicos) y protección (usuarios y procesos solo acceden a lo autorizado).

                                    
Sus funciones observables son gestión de procesos (planificación con quantum, concurrencia en un núcleo y paralelismo real en varios, CFS/EEVDF en Linux y colas multinivel en Windows 11), de memoria, de ficheros, de dispositivos de E/S, de usuarios y seguridad, y de comunicaciones. Internamente separa el espacio de usuario (privilegios restringidos, GUI o CLI) del espacio del núcleo: una llamada al sistema (system call) cambia a modo núcleo, el kernel atiende la petición y devuelve el control.

                                    
Los controladores traducen las órdenes genéricas del SO a dispositivos concretos (impresora, GPU, adaptador de red); sin ellos el hardware compatible puede quedar inutilizable. El firmware puede incorporar incluso un sistema operativo embebido o un RTOS, donde importa más cumplir el plazo que ir rápido. En cuanto al marco legal, una licencia regula uso, copia, modificación y redistribución: propietario frente a libre, modalidades OEM/Retail/volumen y modelos de suscripción; GPL es copyleft, mientras que MIT y Apache 2.0 son permisivas, y libre no significa gratuito (RHEL frente a Chrome).

                                    
    
                                        
  • Sistema vs aplicación: Windows 11, Ubuntu, drivers y utilidades son sistema; VLC, 7-Zip o el navegador son aplicación.
    • 
                                        
  • Abstracción: copiar un archivo es arrastrarlo entre carpetas; internamente hay bloques, permisos y controladores.
    • 
                                        
  • Protección: autenticación, permisos, privilegios y aislamiento; se aplica igual en GUI que en CLI.
    • 
                                        
  • Procesos: la multitarea apropiativa retira la CPU al agotar el quantum; en un solo núcleo hay concurrencia, no paralelismo real.
    • 
                                        
  • Arquitectura: modo usuario → llamada al sistema → modo núcleo → kernel (planificación, memoria, dispositivos) → respuesta.
    • 
                                        
  • Controladores y firmware: hacen usable el hardware; un error en modo núcleo puede afectar a todo el sistema.
    • 
                                        
  • Licencias: OEM queda ligada al primer equipo, Retail suele transferirse, volumen permite activación centralizada KMS/MAK; GPL exige mantener la licencia al redistribuir derivados.
    • 
                                    

                                    

                                        
Ejemplo · guardar un archivo desde la aplicación hasta el SSD

                                        
Aplicación: el usuario pulsa Guardar en el editor
1. Biblioteca de usuario → llamada al sistema write()
2. Cambio de modo usuario a modo núcleo
3. Gestor de ficheros: nombre de archivo → entrada MFT/inode + comprobación de permisos
4. Gestor de memoria: copia el búfer de la aplicación a un búfer del kernel
5. Controlador del SSD: convierte bloques en sectores y ordena la escritura
6. Kernel devuelve "OK" → la aplicación muestra "Guardado"

                                        
Cadena: aplicación → system call → kernel → sistema de ficheros → controlador → SSD
Usuario "ana" con permiso de escritura → Guardado correcto (1 archivo, 4 KB)
Usuario "invitado" sin permiso → Acceso denegado (el kernel bloquea la operación)
Sin controlador del SSD → el dispositivo no aparece aunque esté físicamente conectado

                                    

                                    

                                        
Ejemplo · decidir licencias para 150 ordenadores

                                        
Centro educativo: 150 PCs con Windows 11 Pro; presupuesto limitado
Opción A: 150 licencias Retail
Opción B: acuerdo de licenciamiento por volumen con activación KMS
Opción C: Ubuntu Desktop 24.04 LTS (kernel GPL, componentes MIT/Apache)

                                        
A: 150 claves independientes; transferibles si se retiran del equipo anterior; coste alto.
B: precio negociado + activación centralizada; NO es comprar 150 Retail con descuento. Elección recomendada.
C: 0 € en licencias; libertad para estudiar/modificar; LTS ofrece soporte prolongado (suscripción opcional).
Caso aislado: portátil con licencia OEM → al cambiar de equipo, la clave normalmente no se traslada.

                                    

                                    
Qué ocurre: El SO oculta la complejidad del hardware mediante abstracciones y calls privilegiadas, y la licencia determina qué se puede hacer legalmente con el programa; confundir "gratuito" con "libre" o "OEM" con "Retail" genera errores de uso y de coste.

                                    
Para qué sirve: Sirve para instalar, administrar y actualizar sistemas operativos con criterio, sabiendo qué hace el kernel, por qué hacen falta drivers y qué derechos concede cada licencia.

                                


                                

                                    
Tema 25 · Temario 03

                                    
Redes, protocolos TCP/IP y seguridad básica

                                    
Una red conecta equipos para compartir datos y recursos. Según su extensión: LAN (aula, oficina), MAN (conjunto de centros de una ciudad) y WAN (países; Internet es la red global). La Intranet es una red privada de la organización, y la Extranet la abre parcialmente a clientes o proveedores. En la topología estrella, cada nodo llega a un switch central; en bus y anillo comparten medio o secuencia, y en malla los caminos son redundantes.

                                    
Los equipos tienen papeles distintos: el switch reenvía por dirección MAC dentro de la LAN, el router conecta redes distintas mediante direcciones IP, el firewall filtra tráfico según reglas y el punto de acceso inalámbrico amplía la red con Wi-Fi. El modelo TCP/IP estructura la comunicación: DHCP asigna IP, máscara, puerta de enlace y DNS al arrancar; DNS traduce nombres a IP; TCP garantiza entrega ordenada; HTTP usa el puerto 80 y HTTPS el 443 con cifrado TLS.

                                    
En el modelo cliente-servidor, el cliente pide y el servidor responde (petición GET y respuesta 200 OK). La seguridad básica combina cifrado, autenticación, permisos, firewall, actualizaciones y copias de seguridad: más conectividad significa también más superficie de ataque, algo crítico cuando la red llega a sistemas que controlan procesos físicos.

                                    
    
                                        
  • LAN/MAN/WAN: alcance local, metropolitano y global; Internet, Intranet y Extranet se diferencian por quién puede acceder.
    • 
                                        
  • Topología estrella: fácil de ampliar y diagnosticar, pero depende del switch central; la malla agrega redundancia.
    • 
                                        
  • Switch: conecta segmentos de una misma red usando MAC; router: une redes con IP; firewall: aplica reglas de entrada/salida.
    • 
                                        
  • IPv4: 32 bits (192.168.1.20/24); IPv6 usa 128 bits para evitar el agotamiento de direcciones.
    • 
                                        
  • DHCP: entrega configuración automática; DNS: resuelve www.ejemplo.com → 203.0.113.10.
    • 
                                        
  • HTTP/HTTPS: mismo servicio web, pero HTTPS añade TLS; el navegador avisa si el certificado no es válido.
    • 
                                        
  • Seguridad: contraseñas fuertes, MFA, menor privilegio, parches, segmentación de red y copias; nunca reutilizar claves entre sistemas IT y OT.
    • 
                                    

                                    

                                        
Ejemplo · de escribir una URL a ver la página

                                        
Cliente con DHCP activo: IP 192.168.1.20/24, gateway 192.168.1.1, DNS 192.168.1.1
Usuario escribe: https://www.ejemplo.com
1. DNS pregunta por www.ejemplo.com
2. El equipo abre conexión TCP al puerto 443 de 203.0.113.10
3. Cliente y servidor negocian TLS
4. Cliente envía GET /index.html HTTP/1.1
5. Servidor responde con la página y el navegador la representa

DNS        UDP 53      www.ejemplo.com → 203.0.113.10
TCP+TLS    puerto 443  handshake correcto, certificado válido

Para qué sirve: Permite diseñar una red pequeña, interpretar una comunicación web y aplicar medidas básicas de seguridad para que datos y servicios lleguen solo a quien debe recibirlos.

                                


                                

                                    
Tema 26 · Temario 03

                                    
Digitalización, datos, procesos y cultura digital

                                    
Digitalizar es obtener una representación digital de la información para almacenarla, procesarla, transmitirla o reproducirla: una señal analógica continua pasa a bits discretos. Un dato es un hecho aislado (21); se convierte en información al interpretarlo (IVA del 21% aplicado a 1.000 € = 210 €). Conviene no confundir tres niveles: digitalizar información cambia el formato (factura escaneada a PDF), digitalizar un proceso cambia la forma de hacer las tareas (recibir, extraer, registrar y comprobar la factura electrónicamente) y la transformación digital revisa toda la organización para trabajar mejor, no por digitalizar.

                                    
La empresa es un conjunto de áreas conectadas: Ventas genera pedidos, Producción consume materiales, Almacén controla existencias, Compras repone, Logística entrega y Administración factura y contabiliza. El caso GEPICS en Opel Zaragoza lo demostraba: la lista digital de vehículos (modelo, color, equipamiento) servía para planificar, prever componentes, agrupar operaciones similares y reducir cambios de herramienta. La Industria 4.0 (cuarta revolución, ~2010) añade IoT/IIoT, nube, Big Data, IA, robótica, gemelos digitales y fabricación aditiva a la automatización previa.

                                    
Las ventajas son menos tareas repetitivas, trazabilidad, coordinación con datos actualizados y mejores decisiones; los riesgos son la dependencia tecnológica, los errores de datos mal gobernados, los ciberataques y la brecha digital. La cultura digital (formación, hábito de medir, colaboración entre áreas) es tan necesaria como la herramienta. El RGPD obliga a minimizar los datos personales, definir una base legal y consentimiento, limitar accesos, garantizar derechos de acceso/rectificación/supresión, cifrar copias y notificar brechas a la autoridad en un plazo de 72 horas; la ética exige además usar los datos y la IA sin sesgos ni finalidades abusivas y asegurar que el acceso a los servicios digitales sea inclusivo.

                                    
    
                                        
  • Analógico → digital: magnitudes continuas se muestrean y codifican en bits; lo importante es qué permite hacer después con esa representación.
    • 
                                        
  • Dato → información: el contexto convierte 30 en "30 pedidos pendientes" o "30 °C en el proceso".
    • 
                                        
  • Tres niveles: formato, proceso y transformación global; escanear no es automatizar.
    • 
                                        
  • Áreas conectadas: una acción de Ventas desencadena decisiones en Producción, Compras, Almacén, Logística y Administración (caso GEPICS).
    • 
                                        
  • Cultura digital: formación del personal, datos compartidos con control, mejora continua y coordinación IT/negocio.
    • 
                                        
  • Ventajas y riesgos: eficiencia y trazabilidad frente a ciberataques, pérdida de privacidad, obsolescencia y exclusión de quien no tiene acceso.
    •

Tema 27 · Temario 03

                                    
Entornos IT y OT, convergencia y plataforma DASP

                                    
Los entornos IT (Information Technology) gestionan información: ERP (SAP, Odoo), CRM, SGBD (PostgreSQL, MySQL), BI (Power BI), correo, servidores, redes y nube. Los entornos OT (Operational Technology) supervisan y actúan sobre el mundo físico con sensores (temperatura, presión, posición, nivel, vibración), actuadores, PLC, HMI, SCADA, CNC y robótica. Regla rápida: si mide o controla una máquina es OT; si gestiona datos del negocio es IT. Sus prioridades también difieren: IT suele velar por confidencialidad e integridad; OT por disponibilidad, seguridad física y respuesta en tiempo real, porque una parada puede detener una línea.

                                    
La digitalización favorece la convergencia IT/OT: los datos de planta alimentan los sistemas de negocio y las decisiones de negocio bajan a las operaciones. Una plataforma tipo DASP (Digital Automation System Platform) actúa como capa de integración industrial: recoge y normaliza datos de sensores, PLC y SCADA, los contextualiza, alimenta cuadros de mando y análisis (BI/IA) y devuelve consignas u órdenes de trabajo al ERP/MES. Su papel no es "conectar cables", sino hacer que información y control fluyan con un modelo común, trazabilidad y reglas de seguridad.

                                    
La convergencia aporta mantenimiento predictivo, mejor coordinación entre áreas y continuidad operativa, pero plantea retos reales: protocolos y arquitecturas distintos, sistemas heredados sin capacidad de conexión, riesgos de ciberseguridad al abrir sistemas físicos, y culturas profesionales diferentes. Por eso se diseñan ventanas de actualización, segmentación de red, redundancia, copias y pruebas antes de tocar un control en marcha; el gemelo digital permite simular cambios sin detener el proceso.

                                    
    
                                        
  • IT: información y procesos de negocio (ERP, CRM, SGBD, BI, correo, nube); prioridad en datos y servicios.
    • 
                                        
  • OT: proceso físico (sensores → PLC → actuadores; HMI y SCADA para supervisar); prioridad en disponibilidad y plazos.
    • 
                                        
  • Diferencias: lenguajes y protocolos propios, ciclos de vida largos, actualizaciones delicadas y impacto directo en personas e instalaciones.
    • 
                                        
  • Convergencia: del ERP a la máquina y de vuelta; un pedido puede ajustar la producción y una alerta de planta puede generar mantenimiento.
    • 
                                        
  • DASP: capa común de ingesta, normalización, supervisión, analítica y retorno de consignas entre OT e IT.
    • 
                                        
  • Mantenimiento: de reactivo a predictivo mediante vibración, temperatura o corriente; órdenes automáticas antes de la avería.
    • 
                                        
  • Continuidad y retos: legacy, ciberseguridad, coordinación IT/OT, ventanas de cambio, redundancia y copias de seguridad.
    •

JDK, JRE, JVM y bytecode: de javac a java (y de la IDE a la terminal)

                                    
El JDK (Java Development Kit) incluye las herramientas de desarrollo —javac, java, jar— y la JRE (Java Runtime Environment), que aporta las bibliotecas y la JVM necesarias para ejecutar. La JVM es la máquina virtual que interpreta el bytecode: un lenguaje máquina estándar al que se compila el código fuente Java; ninguna máquina física lo usa directamente, así que hace falta la JVM para traducirlo a las instrucciones del ordenador concreto.

                                    
El recorrido es App.java → javac App.java → App.class (bytecode) → java App → JVM. La JVM traduce instrucción a instrucción, más lentamente que el código máquina, pero gana portabilidad; además usa compiladores JIT (Just In Time) que guardan traducciones en un buffer para acelerar ejecuciones posteriores. Por eso el mismo .class funciona en cualquier sistema con una JVM compatible, sin recompilar para cada máquina.

                                    
Los IDE ejecutan esos mismos comandos detrás de un botón, pero la terminal permite ver con precisión qué falla. Conviene distinguir un error de compilación (el fuente no se convierte en bytecode y no aparece el .class) de un error de ejecución (el bytecode existe y la JVM lanza una excepción). En la práctica se comprobó también el ciclo de vida de Maven y sus repositorios: Maven gestiona dependencias y fases de construcción, mientras que la compilación y la ejecución siguen siendo obra del JDK.

                                    
    
                                        
  • JDK / JRE / JVM: el JDK desarrolla, la JRE aporta entorno de ejecución y la JVM interpreta bytecode.
    • 
                                        
  • javac: compila el código fuente y genera archivos .class con bytecode.
    • 
                                        
  • java: inicia la JVM y ejecuta la clase indicada; java -jar ejecuta un JAR empaquetado.
    • 
                                        
  • Classpath: -cp . indica dónde buscar clases y dependencias; sin él aparece ClassNotFoundException.
    • 
                                        
  • Bytecode: código máquina estándar e independiente de la plataforma, no código máquina nativo.
    • 
                                        
  • Errores: de compilación antes de generar .class; de ejecución durante la interpretación del bytecode.
    • 
                                        
  • IDE frente a terminal: el IDE automatiza, la terminal muestra los comandos y mensajes exactos del JDK.
    • 
                                        
  • Maven: gestiona el proyecto, sus dependencias y su ciclo de vida; la configuración se comparte entre IDEs.
    •

Tema 32 · Temario 05

                                    
El lenguaje HTML: historia, sintaxis y elementos de una página web

                                    
Un lenguaje de marcado no es un lenguaje de programación: describe cómo se organiza la información insertando marcas, las etiquetas, que delimitan el contenido. HTML (HyperText Markup Language) fue diseñado en 1991 por Tim Berners-Lee en el CERN para almacenar y transmitir información. Nació con 18 etiquetas y se caracteriza por ser sencillo, flexible, universal, accesible, fácil de usar y de uso libre; hoy cuenta con más de 140 etiquetas.

                                    
La evolución es continua: diseño inicial en 1991 como dialecto de SGML, HTML 1.1 (1992), HTML 2.0 publicado en el IETF (1995), HTML 3.2 y HTML 4 como recomendaciones del W3C (1997), HTML 4.1 (1999), XHTML (2000), HTML 5.0 (2014), 5.1 (2016) y 5.2 (2017). Cada versión incorpora, elimina y actualiza etiquetas. Si un navegador encuentra un error en el código, normalmente lo corrige y sigue mostrando la página en lugar de detenerse.

                                    
El documento es jerárquico: <html> es el elemento raíz, <head> contiene los metadatos no visibles y <body> el contenido visible. Las etiquetas pueden tener atributos, deben anidarse correctamente y se clasifican en elementos de bloque y de línea. También forman parte del día a día las entidades para caracteres especiales, los comentarios, las tablas y el estilo básico con CSS.

                                    
    
                                        
  • Un elemento se escribe con etiqueta de apertura <p> y de cierre </p>; los elementos vacíos, como <br>, <hr> o <img>, no tienen contenido ni etiqueta de cierre en HTML5.
    • 
                                        
  • Los atributos van en la etiqueta de apertura, por ejemplo <a href="pagina.html">; entre los globales están id, class, lang, title, style, tabindex, hidden, spellcheck y contenteditable.
    • 
                                        
  • El anidamiento debe cerrar los elementos en orden inverso al de apertura: solapar <em> y <strong> es un error que el navegador intentará reparar.
    • 
                                        
  • Estructura básica: <!DOCTYPE html>, <html lang="es">, <head> con <meta charset="UTF-8"> y <title>, y <body> con el contenido.
    • 
                                        
  • Metadatos habituales: charset, viewport, description, author, robots y http-equiv; no se ven, pero afectan a la interpretación, el SEO y la representación móvil.
    • 
                                        
  • Elementos de bloque (<h1> a <h6>, <p>, <ul>, <ol>, <table>) ocupan el ancho del contenedor y provocan salto de línea; los de línea (<a>, <strong>, <em>, <code>, <img>) ocupan solo lo que mide su contenido.
    • 
                                        
  • Entidades como <, >, &,   y € permiten mostrar caracteres especiales; los comentarios <!-- ... --> no aparecen en la página.
    • 
                                        
  • CSS básico con <style> o el atributo style (color, background-color, font-size) y tablas con <table>, <caption>, <thead>, <tbody>, <tfoot>, <tr>, <th>, <td>, colspan y rowspan.
    • 
                                    

                                    

                                        
Ejemplo · Documento HTML5 mínimo con metadatos y estilo

                                        
<!DOCTYPE html>
<html lang="es">
<head>
<meta charset="UTF-8">
<title>Mi primera página</title>
<style>body { background-color: powderblue; }</style>
</head>
<body>
<h1>¡HOLA!</h1>
<!-- Esta es mi primera página HTML -->
</body>
</html>

                                        
El navegador muestra un fondo azul claro y, arriba, el texto «¡HOLA!» en grande y en negrita como encabezado. En la pestaña se lee «Mi primera página». El comentario no se muestra.

                                    

                                    

                                        
Ejemplo · Texto, enlaces, listas y entidades

                                        
<p>Una olla de algo más vaca que <a href="https://dle.rae.es/carnero" target="_blank">carnero</a>, salpicón las más noches...</p>
<ul>
<li>Estudiar <strong>HTML</strong></li>
<li>Practicar con <code>&lt;h1&gt;</code></li>
</ul>
<p>5 &lt; 6 y 4 &amp; 7 son ejemplos de entidades.</p>

                                        
Un párrafo con la palabra «carnero» como enlace que se abre en una pestaña nueva; debajo, una lista con dos viñetas: «Estudiar HTML» (con HTML en negrita) y «Practicar con <h1>» (con <h1> con aspecto de código); por último, la línea «5 < 6 y 4 & 7 son ejemplos de entidades.»

                                    

                                    

                                        
Ejemplo · Tabla con cabecera, cuerpo y pie

                                        
<table>
<caption>Consolas</caption>
<thead>
<tr><th>Consola</th><th>Lanzamiento</th></tr>
</thead>
<tbody>
<tr><td>PS1</td><td>1994</td></tr>
<tr><td>PS2</td><td>2000</td></tr>
</tbody>
<tfoot>
<tr><td colspan="2">Dos consolas</td></tr>
</tfoot>
</table>

                                        
Una tabla con el título «Consolas» encima, una cabecera con las columnas «Consola» y «Lanzamiento» (normalmente en negrita), dos filas «PS1 | 1994» y «PS2 | 2000», y una última fila de pie con una sola celda que abarca las dos columnas y dice «Dos consolas».

                                    

                                    
Qué ocurre: <table> es el contenedor, <thead>, <tbody> y <tfoot> organizan las zonas, <th> marca las celdas de encabezado y colspan="2" hace que la celda del pie ocupe dos columnas.

                                    
Para qué sirve: Servir para presentar datos tabulares de forma clara y agrupar lógicamente encabezados, datos y resumen final.

                                


                                

                                    
Tema 33 · Temario 05

                                    
XHTML: la versión XML de HTML

                                    
XHTML significa eXtensible HyperText Markup Language: es la versión XML de HTML. Utiliza las mismas etiquetas que HTML, pero las somete a las reglas estrictas de XML. Fue recomendación del W3C en el año 2000 con el propósito de sustituir a HTML 4.1, y sus archivos usan la extensión .xhtml.

                                    
Las diferencias principales son de sintaxis: todos los elementos deben cerrarse, incluso los vacíos; los elementos no vacíos sin contenido no pueden cerrarse de forma abreviada; el anidamiento debe ser correcto; se distingue entre mayúsculas y minúsculas, por lo que las etiquetas van en minúsculas; los valores de los atributos deben ir entre comillas y todos los atributos necesitan un valor. El documento lleva una declaración XML, un DOCTYPE (por ejemplo XHTML 1.0 Strict) y un elemento raíz <html> con el espacio de nombres xmlns.

                                    
Conviene distinguir bien formado de válido: un documento bien formado cumple la sintaxis XML; es válido si, además, respeta la DTD declarada, que en Strict prohíbe elementos de presentación como <b> o atributos como bgcolor. Ante un error, un procesador XML se detiene y lo informa, mientras que HTML suele corregirlo sobre la marcha. Esa rigidez, junto con la aparición de HTML5 con sintaxis tolerante, etiquetas semánticas y multimedia sin exigir XML, hizo que XHTML perdiera terreno; hoy se suele escribir HTML5 con buena sintaxis por disciplina, no XHTML puro.

                                    
    
                                        
  • XHTML es HTML con las reglas de XML: mismo vocabulario de etiquetas y sintaxis mucho más exigente.
    • 
                                        
  • Todo elemento se cierra: <p>texto</p> y los vacíos con barra final, <br /> o <img src="logo.png" alt="Logo" />.
    • 
                                        
  • Elementos no vacíos sin contenido se cierran con etiqueta completa, <p></p>, nunca de forma abreviada <p />.
    • 
                                        
  • Etiquetas y atributos siempre en minúsculas, porque XML distingue mayúsculas de minúsculas: <body>, no <BODY>.
    • 
                                        
  • Comillas obligatorias en todos los valores, también los numéricos: <td colspan="2">; y ningún atributo queda sin valor: selected="selected".
    • 
                                        
  • Anidamiento sin solapes y un único elemento raíz <html xmlns="http://www.w3.org/1999/xhtml" xml:lang="es" lang="es">.
    • 
                                        
  • DOCTYPE y declaración XML: <?xml version="1.0" encoding="UTF-8"?> y <!DOCTYPE html PUBLIC "-//W3C//DTD XHTML 1.0 Strict//EN" "...">.
    • 
                                        
  • Bien formado significa cumplir XML; válido significa cumplir además la DTD. Un error XML detiene el procesamiento, mientras que HTML lo corrige y continúa.
    • 
                                    

                                    

                                        
Ejemplo · Documento XHTML 1.0 Strict completo

                                        
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE html PUBLIC "-//W3C//DTD XHTML 1.0 Strict//EN" "http://www.w3.org/TR/xhtml1/DTD/xhtml1-strict.dtd">
<html xmlns="http://www.w3.org/1999/xhtml" xml:lang="es" lang="es">
<head>
<meta http-equiv="Content-Type" content="text/html; charset=UTF-8" />
<title>Mi primer documento XHTML</title>
</head>
<body>
<h1>Hola, mundo</h1>
<p>Este es un párrafo de ejemplo en XHTML.</p>
</body>
</html>

                                        
El navegador muestra el encabezado «Hola, mundo» y, debajo, el párrafo «Este es un párrafo de ejemplo en XHTML.». En la pestaña se lee «Mi primer documento XHTML». La declaración XML, el DOCTYPE y los atributos no aparecen.

                                    

                                    

                                        
Ejemplo · Fragmento XHTML bien formado con atributos citados

                                        
<p>Estudio <abbr title="Extensible HyperText Markup Language">XHTML</abbr><br />y aplico reglas XML.</p>
<dl>
<dt>HTML</dt>
<dd>Lenguaje de marcado de hipertexto</dd>
</dl>

                                        
Aparece «Estudio XHTML» en una línea y «y aplico reglas XML.» en la siguiente. Al situar el cursor sobre XHTML se muestra como sugerencia «Extensible HyperText Markup Language». Después se lee «HTML» y, debajo y sangrada, «Lenguaje de marcado de hipertexto».

                                    

                                    

                                        
Ejemplo · Sintaxis HTML5 tolerante frente a XHTML

                                        
<p>Primera línea<br>Segunda línea</p>

                                        
El navegador muestra «Primera línea» y en la línea siguiente «Segunda línea», sin ningún aviso; sin embargo, un procesador XHTML rechazaría este fragmento porque <br> no lleva la barra de cierre.

                                    

                                    
Qué ocurre: HTML5 permite omitir la barra en los elementos vacíos y los navegadores reparan la sintaxis, mientras que XHTML exige <br /> y trata la omisión como un error de análisis que detiene el procesamiento.

                                    
Para qué sirve: Servir para entender por qué HTML5 desplazó a XHTML: mantiene una sintaxis cómoda y tolerante sin renunciar a escribir código limpio y cerrado.

                                


                                

                                    
Tema 34 · Temario 05

                                    
Formularios: recoger datos y enviarlos al servidor

                                    
Un formulario es la herramienta de HTML para recoger información del usuario y enviarla a un servidor. Se delimita con el elemento <form>, cuyo atributo action indica la dirección que procesará los datos y cuyo atributo method decide cómo se envían. Sin esos atributos, el propio formulario se envía a la página actual.

                                    
Los controles más habituales son <input>, con tipos text, password, checkbox, radio, submit y hidden; <textarea> para textos largos; <select> junto con <option> para listas desplegables; y <button> para acciones. Cada control lleva un atributo name, que es el nombre con el que el dato llega al servidor, y un id que permite asociarle una <label> mediante for. <fieldset> y <legend> agrupan y rotulan conjuntos de controles.

                                    
La elección entre GET y POST es importante: GET añade los valores a la URL (?usuario=ana&nivel=1), es visible, queda en el historial y tiene longitud limitada, por lo que conviene para consultas; POST los envía en el cuerpo de la petición, no los muestra en la dirección y permite más datos, por lo que se usa para contraseñas o envíos. La validación en cliente con required, type="email" o pattern ayuda al usuario, pero el servidor debe validar siempre los datos recibidos.

                                    
    
                                        
  • <form action="procesar.php" method="post"> define el destino y el método de envío de todos los controles que contiene.
    • 
                                        
  • <input type="text" name="usuario"> crea un campo de una sola línea; name identifica el valor que se enviará.
    • 
                                        
  • type="password" enmascara lo escrito y type="hidden" transporta un valor invisible para el usuario, como un token o un identificador.
    • 
                                        
  • type="checkbox" admite varias opciones marcadas; type="radio" con el mismo name permite elegir solo una.
    • 
                                        
  • type="submit" genera el botón de envío; <button type="submit"> es una alternativa más flexible para personalizar el botón.
    • 
                                        
  • <textarea name="mensaje" rows="4" cols="30"> admite texto multilínea y su contenido inicial se escribe entre la etiqueta de apertura y la de cierre.
    • 
                                        
  • <select name="nivel"> con <option value="basico"> y <option value="avanzado" selected> ofrece una lista desplegable con una opción preseleccionada.
    • 
                                        
  • <label for="id"> hace clicable el texto del control y lo nombra para lectores de pantalla; <fieldset> y <legend> agrupan, y required, pattern o minlength validan en el cliente sin sustituir la validación del servidor.
    • 
                                    

                                    

                                        
Ejemplo · Formulario de acceso enviado con GET

                                        
<form action="/buscar" method="get">
<label for="usuario">Usuario:</label>
<input type="text" id="usuario" name="usuario" required>
<label for="clave">Contraseña:</label>
<input type="password" id="clave" name="clave">
<input type="hidden" name="origen" value="login">
<input type="submit" value="Entrar">
</form>

                                        
Se ven las etiquetas «Usuario:» y «Contraseña:», dos cuadros de texto (el segundo muestra puntos o asteriscos en lugar de los caracteres) y un botón «Entrar». El campo oculto no aparece. Al pulsar «Entrar», la URL pasa a ser /buscar?usuario=...&clave=...&origen=login.

                                    

                                    

                                        
Ejemplo · Encuesta con POST, select, textarea y fieldset

                                        
<form action="/encuesta" method="post">
<fieldset>
<legend>Datos de contacto</legend>
<label for="nombre">Nombre:</label>
<input type="text" id="nombre" name="nombre"><br>
<label for="nivel">Nivel:</label>
<select id="nivel" name="nivel">
<option value="basico">Básico</option>
<option value="avanzado" selected>Avanzado</option>
</select><br>
<label for="comentarios">Comentarios:</label>
<textarea id="comentarios" name="comentarios" rows="3">Escribe aquí</textarea><br>
<input type="checkbox" id="news" name="news" value="si" checked>
<label for="news">Recibir novedades</label><br>
<input type="submit" value="Enviar">
</fieldset>
</form>

                                        
Un recuadro con la leyenda «Datos de contacto» contiene el campo «Nombre:», la lista «Nivel:» con «Básico» y «Avanzado» (esta última seleccionada), un área de texto de tres filas con «Escribe aquí», la casilla «Recibir novedades» marcada y el botón «Enviar».

                                    

                                    

                                        
Ejemplo · Validación de correo en el navegador

                                        
<form action="/alta" method="post">
<label for="correo">Correo:</label>
<input type="email" id="correo" name="correo" required pattern=".+@ejemplo\.com">
<input type="submit" value="Registrarse">
</form>

                                        
Se muestran el campo «Correo:» y el botón «Registrarse». Si se pulsa el botón con el campo vacío o con una dirección que no cumple el formato, el navegador muestra un aviso y no envía nada; si es válido, los datos se envían a /alta mediante POST.

                                    

                                    
Qué ocurre: required exige un valor, type="email" comprueba el formato general de correo y pattern añade una expresión regular; el navegador aplica estas reglas antes de enviar, pero el servidor debe repetir la comprobación.

                                    
Para qué sirve: Servir para evitar envíos incompletos o mal formados y ofrecer feedback inmediato al usuario sin sustituir nunca la validación en servidor.

                                


                                

                                    
Tema 35 · Temario 05

                                    
Accesibilidad, semántica y buenas prácticas en HTML

                                    
Accesibilidad significa que cualquier persona, también con limitaciones visuales, auditivas o motoras, pueda usar la página. La base es la semántica: elegir la etiqueta que describe la función real del contenido. El temario destaca que HTML5 incorpora etiquetas semánticas como <header>, <nav>, <main>, <section>, <article>, <aside> y <footer>, frente a los genéricos <div> y <span>, que no indican qué contenido albergan ni qué función cumplen.

                                    
El atributo lang declara el idioma del documento o de un fragmento; el atributo alt describe las imágenes; el contraste entre texto y fondo debe ser suficiente; y la navegación con teclado debe funcionar con un orden lógico y un foco visible. WAI-ARIA añade información para tecnologías asistivas mediante role, aria-label, aria-expanded o aria-hidden, pero no sustituye a los elementos nativos.

                                    
Las buenas prácticas incluyen validar el documento con el W3C Markup Validation Service, que permite hacerlo por URI, subiendo el archivo o pegando el código, y que para HTML5 emplea el validador validator.nu. También importan el SEO y el rendimiento: metadatos útiles, enlaces descriptivos, imágenes comprimidas y CSS bien organizado. Deben evitarse elementos obsoletos como <font>, <center>, <big> o <frame> y atributos de presentación como bgcolor, sustituyéndolos por CSS y etiquetas semánticas.

                                    
    
                                        
  • Semántica HTML5: <header> cabecera, <nav> navegación, <main> contenido principal, <section> sección, <article> unidad independiente, <aside> contenido relacionado y <footer> pie de página.
    • 
                                        
  • Un solo <main> por página y encabezados jerárquicos <h1> a <h6> sin saltos arbitrarios de nivel.
    • 
                                        
  • <img> siempre con alt descriptivo; si la imagen es decorativa, alt="" para que los lectores de pantalla la omitan.
    • 
                                        
  • lang="es" en <html>, y lang="en" en fragmentos en otro idioma: ayuda a la pronunciación, la traducción y la comprensión del texto.
    • 
                                        
  • Contraste suficiente entre texto y fondo, tamaños legibles y nunca comunicar información solo mediante el color.
    • 
                                        
  • Navegación con teclado: orden de tabulación natural, tabindex solo cuando haga falta, foco visible y enlaces con texto descriptivo en lugar de «haz clic aquí».
    • 
                                        
  • WAI-ARIA básico: role, aria-label, aria-expanded y aria-hidden solo para aportar función o estado que la etiqueta nativa no expresa.
    • 
                                        
  • Validar con el servicio del W3C, cuidar SEO y rendimiento (title, description, viewport, imágenes optimizadas) y evitar <font>, <center>, <big>, <frame> y bgcolor en favor de CSS.
    • 
                                    

                                    

                                        
Ejemplo · Estructura semántica de una página

                                        
<header>
<h1>Mi sitio</h1>
<nav aria-label="Navegación principal">
<a href="/inicio">Inicio</a> | <a href="/temas">Temas</a>
</nav>
</header>
<main>
<article>
<h2>Primer artículo</h2>
<p>Contenido del artículo.</p>
</article>
<aside>
<h2>Relacionado</h2>
<p>Otros artículos.</p>
</aside>
</main>
<footer><p>Diseñado por DAM1</p></footer>

                                        
Arriba se lee «Mi sitio» como título grande y debajo los enlaces «Inicio | Temas». En el contenido principal aparece «Primer artículo» con su párrafo y, a un lado, «Relacionado» con «Otros artículos». En la parte inferior se ve «Diseñado por DAM1».

                                    

                                    

                                        
Ejemplo · Imagen con texto alternativo e idioma declarado

                                        
<html lang="es">
<body>
<p>En la clase de <abbr lang="en" title="HyperText Markup Language">HTML</abbr> vimos esta imagen:</p>
<img src="logo.png" alt="Logotipo del instituto con las siglas IES">
</body>
</html>

                                        
Se lee «En la clase de HTML vimos esta imagen:» y debajo aparece la imagen logo.png. Si la imagen no se carga o se usa un lector de pantalla, se presenta el texto «Logotipo del instituto con las siglas IES». Al pasar el cursor por HTML se muestra «HyperText Markup Language».

                                    

                                    

                                        
Ejemplo · ARIA básico sin renunciar a elementos nativos

                                        
<nav aria-label="Menú lateral">
<ul>
<li><a href="/apuntes">Apuntes</a></li>
</ul>
</nav>
<p role="note">Recuerda validar el HTML en el servicio del W3C.</p>

                                        
Se ve una lista con el enlace «Apuntes» y, debajo, el párrafo «Recuerda validar el HTML en el servicio del W3C.». No aparece el texto «Menú lateral»: aria-label solo lo anuncian las tecnologías asistivas.

                                    

                                    
Qué ocurre: aria-label da un nombre accesible al elemento <nav> sin añadir texto visible y role="note" comunica el propósito del párrafo, mientras que <a> y <ul> siguen siendo navegables con teclado por ser elementos nativos.

                                    
Para qué sirve: Servir para reforzar la información accesible cuando la semántica HTML no basta, sin romper la navegación ni duplicar contenido visible.
